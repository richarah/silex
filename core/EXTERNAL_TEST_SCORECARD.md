# External Test Suite Scorecard

**Measured:** 2026-08-14, monorepo `core/`, glibc x86_64. Supersedes the
2026-08-10/11/12 figures. This round: coreutils re-measured on a native
filesystem (**0 failures**, the previous 27 were drvfs's no-op chmod), and
the Oils suite converted from a score into a gap finder via a per-case
silex-vs-dash differential (**198 -> 167 -> 107 -> 86 -> 71** real POSIX
gaps as the queue was worked; silex now passes **1053** of the 2802 cases
to dash's 957).

Before trusting any number here, read why an earlier version of this file was
meaningless.

## Why the old numbers were meaningless

Every gate in the test infrastructure was once wired so it could not report
failure:

- **Six runners ended in a hardcoded `exit 0`.**
- **`run-configure.sh` tested `tail`'s exit status**, not configure's
  (`if cmd | tail -50; then`). `FAIL` could never increment, so the report
  always said `Failed: 0` — the exact string CI grepped for. A run in which
  curl's configure died with `'echo' command not found` was recorded as
  **5/5 PASS**.
- **`run-modernish.sh` counted `^FTL` lines with `grep -c … || true`.** When
  modernish failed to launch, the count was 0, so the suite reported
  *"Fatal bugs (FTL): 0 — Perfect score!"* — a clean sheet awarded *because*
  it was too broken to run.
- **CI's "critical requirements" step treated a missing results file as a
  pass.** Eight of ten suites executed **zero tests** (a relative binary path
  broke after each runner `cd`'d into its own repo).
- The vendored **smoosh checkout had been corrupted by in-place runs**: ~50
  `.out`/~180 `.err` expected-output files had been *generated by silex itself*,
  so those tests compared silex against its own output and passed by
  construction.

That is fixed. Suites can now fail, and a suite that executes zero tests is a
failure, not a pass.

## Where the last smoosh failure is

One test, and it is unwinnable by construction: `builtin.times.ioerror`
compares stderr against the literal line `smoosh: times: I/O error` — the
reference implementation's own name. Every cluster that was listed here on
2026-08-10 (job control/monitor, traps in sub/supershells, non-lexical
break/continue, interactive features, parse-error exit paths, builtin flag
gaps) is fixed and green.

Known real gaps that remain: **71 Oils cases where dash passes and silex
does not** — that list is the POSIX to-do queue, and it is now generated
mechanically (see below). sed's dot-matches-NUL corner needs a
length-aware regex engine. The coreutils suite must be run from
`run-gnu-coreutils-native.sh`; measured in place on /mnt/c its
permission tests are meaningless.

### What the 2026-08-13 queue run fixed (167 -> 107)

Working that queue file by file drove out 50+ POSIX bugs. The ones worth
knowing about:

- **`set -` / `set +`**: a lone `-` turns off `-x`/`-v` and stops option
  processing without clearing `$@`; a lone `+` is an ignored flag. `set - a b`
  used to produce the positionals `- a b`.
- **`-v` (verbose) is implemented**, not just accepted: the lexer echoes input
  to stderr as it consumes it, so `sh -v script` and `set -v` behave like dash.
  `$-` now also reports `v` and `i`.
- **Quoted nulls are fields.** `""$A` with `A="  abc  "` yields `["", abc]` —
  an empty quoted region left nothing for the splitter to see, so the field
  vanished. A zero-width placeholder now carries it through the split.
- **Mixed `$x"$@"` words** split on IFS *and* on the `"$@"` boundaries;
  previously the `"$@"` path returned early and glued `$x` to `$1`.
- **Arithmetic is pre-expanded** (POSIX 2.6.4): `$((1 + $(echo 1)${u:-3}))`,
  `$((1 + $((2+3))))` and backticks all work, newlines are whitespace inside
  `$(( ))`, and trailing garbage (`$((1 + 2.3))`, `$((echo hi))`) is the shell
  error it should be instead of a silent `0`.
- **POSIX 2.8.1 error consequences**: assigning to a read-only variable, and a
  usage error in a special builtin (`set -o bogus`, `shift 3`, `trap -1`), end
  a non-interactive shell — `|| true` does not rescue them.
- **`trap 0 2` resets** those conditions instead of installing an action named
  "0"; `trap 'foo'` with no condition is an error.
- **`wait`** takes several pids, reports the last one's status, returns 127 for
  a pid that is not our child, 2 for a non-numeric operand, and 0 for a plain
  `wait`.
- **Async fork race**: signals are blocked across the `&` fork, so a signal
  aimed at the new job before it cleared the inherited handlers no longer runs
  the parent's trap action twice.
- **Assignment-only commands take their redirections first**, so
  ``paths=`tr '\n' ':'`<<EOF`` reads the here-document. It previously read the
  shell's own stdin and **hung**.
- **Lexer**: a `$` that starts no expansion is literal and does not swallow the
  next character — `"$"` no longer eats its closing quote (the rest of the line
  joined the word) and `echo $;` no longer eats the `;`.
- Plus `getopts` (bad name, OPTIND past a bad flag, reset on `set`), `read`
  option validation, `pwd` after the cwd is removed, `chdir`, `${###}`,
  `test -a FILE`, `PS4` expansion (with the fork bomb that hid in it),
  `sh -l`, `sh -oo a b`, and `set -o vi/emacs`.

### What the 2026-08-14 queue run fixed (107 -> 86)

Twenty-one cases, from six files' worth of queue. One parser bug accounted
for a third of them:

- **`N >` is not a file descriptor.** POSIX 2.10.2 rule 2 makes a digit word an
  IO_NUMBER only when the redirect operator follows with NO blank between
  them; the lexer never recorded adjacency, so `seq 5 6 > f` ran `seq 5` and
  pointed **fd 6** at the file, and `bytes 512 > ok.txt` called the function
  with no arguments at all. Any command whose last operand was numeric and
  was followed by a redirect silently lost that operand. Tokens now carry a
  `blank_before` flag. This alone fixed `redirect-command` 3 and 6,
  `builtin-process` 21, `redirect` 5 and `smoke` 9.
- **A redirect cannot prefix a compound command.** `>f for i in ...` has no
  production in the grammar; it parsed as a redirect-only command followed by
  an unredirected loop, so the output the script meant to capture went to the
  terminal. Now a syntax error (status 2), as in dash. Fixed `assign` 9 too.
- **`set -e` and `!`.** POSIX 2.9.2 exempts a pipeline beginning with `!` --
  and that covers the pipeline's OWN result, not just the negated command.
  Running the inner command in a condition context was not enough: `! true`
  inverted 0 to 1 and the shell then died on the 1.
- **NUL bytes are dropped, not terminators.** A shell variable is a C string,
  so `s=$(printf '.\0.')` truncated at the NUL and threw away the rest. dash
  and bash skip NULs and keep the remainder; command substitution and `read`
  now do the same, which also settles the `${s#?}` cases from Oils issue 2269.
- **`command -p` was parsed and then ignored** on the execution path (only
  `-v` honoured it), so it would happily run a utility the caller had planted
  on `$PATH` -- the one thing `-p` exists to prevent.
- **`ulimit` validation**: extra operands were dropped and `strtoull` was fed
  the sign, so `ulimit -f -- -42` wrapped to a limit of 2^64-42 blocks and
  reported success. Extra operands, `-a` with an operand, and negative numbers
  are now errors (status 2), and `trap`/`kill` learned the rest of the POSIX
  signal names (`XFSZ`, `XCPU`, `VTALRM`, `PROF`, `SYS`, `IO`/`POLL`) -- a
  script's `trap - XFSZ` before deliberately exceeding `ulimit -f` used to
  fail with "bad trap".
- **`date` operands**: a bare operand is the obsolescent
  `MMDDhhmm[[CC]YY][.ss]` set-the-clock form, not a format string, and there
  is at most one `+FORMAT`. `date %x` printed the current time and exited 0
  where every other date rejects it, so a configure probe that tests
  `date FMT` to choose a code path took the wrong branch.

### What the second 2026-08-14 queue run fixed (86 -> 71)

Fifteen cases from five root causes. Two of them were not POSIX corner cases
at all but bugs that silently corrupted ordinary scripts, and both were found
only because the queue pointed at the file:

- **`env CMD` replaced the shell.** `env` EXECS the command it is given --
  correct for a standalone /usr/bin/env, fatal for an applet dispatched
  in-process. `echo a; env echo b; echo c` printed a and b and then the shell
  was simply gone: exit 0, `c` never reached, no diagnostic. Applets are
  dispatched ahead of PATH by design, so this hit every `env CMD` in every
  script. It now runs in a fork, as the `sh` applet already did for the same
  reason. Fixed `shell-bugs` 0 and `tilde` 13.
- **A `VAR=val` prefix never reached an APPLET's environment.** An external
  utility gets the binding from the exec and a shell builtin had its own
  apply/restore, but an applet runs in-process and reads getenv(), so the
  binding was invisible: `TZ=UTC date` printed local time and `LC_ALL=C sort`
  sorted in the caller's locale. Both silently produced wrong output rather
  than failing. The restore covers the export FLAG too, so a variable that
  existed unexported is not left exported.
- **A command whose words expand to NOTHING** still performs its
  redirections and assignments and completes with the status of the last
  command substitution (POSIX 2.9.1). silex returned 0 and did none of it:
  `$(exit 42)` reported success, `set -e; $(false)` did not fire, `$u > f`
  never created f, and `foo=alive! $unset` rolled the binding back with the
  temp overlay instead of keeping it. Which substitution is "last" follows
  POSIX expansion order -- words (step 2) before assignments (step 4) -- so
  `foo=$(exit 1) $(exit 2)` is 1, not 2. Fixed `exit-status` 8, 9 and 10 and
  `temp-binding` 3 (Oils #2411, #2416).
- **`test`/`[` now follows dash's expression grammar** in the three places
  POSIX leaves the form unspecified: a primary that runs out of words is a
  missing expression (false) rather than a syntax error, which is the whole
  `[ -a -a -a ... ]` ladder; a binary operator beats a unary one but only
  when its right operand exists (`test x -a -f = y` is the string compare
  "-f" = "y", while `[ x -a -e = ]` is a file test on "="); and `-t` with a
  non-numeric operand is status 2, not a quiet false. `test $# -ne 0 -a
  "$1" != "--"` -- the sqsh configure idiom behind Oils #2409 -- is the case
  that cares. Fixed `blog2` 1/3/5/7, `bool-parse` 0, `builtin-bracket` 30.
- **`printf` never recognised `--`**, so it took "--" itself as the FORMAT
  and swallowed every argument, printing a bare "--" and exiting 0. And
  `head`/`tail` accepted `--bytes=4` but not `--bytes 4`, which getopt_long
  takes for the same option -- that is what made `builtin-umask` 7 look like
  a umask bug when the umask output was fine and the pipeline's `tail` was
  not. Fixed `builtin-printf` 8 and 9, `builtin-umask` 7.

Two deliberate divergences remain:

- After an expansion error (`set -u`, or `${x?msg}`) an INTERACTIVE silex
  aborts only the offending command and keeps running the rest of the input,
  where dash and bash discard the whole input line. smoosh's
  `semantics.interactive.expansion.exit` requires silex's behaviour and Oils'
  `builtin-set` case 5 requires dash's; silex follows smoosh, its POSIX
  ground truth, and the Oils case stays in the gap list.
- **Applets are dispatched before the PATH search**, so a `tr` earlier on
  `$PATH` does not shadow silex's in-process `tr`, and `command -v tr` names
  the builtin rather than a path. POSIX 2.9.1.1 permits a found utility to
  fall back to the built-in version, and dispatching in-process is the point
  of the monolith; `builtin-meta` cases 1 and 10 want dash's answer and stay
  in the gap list. Note that this is about the shell's own dispatch: the
  toybox and coreutils runners exercise the applets through a PATH of silex
  symlinks and are unaffected.

## Finding real gaps: the silex-vs-dash differential

The Oils suite is mostly bash/ksh extension tests that no POSIX shell
passes, so its raw pass count says little. Running BOTH shells in one
sh_spec.py invocation and diffing per case separates signal from noise.
That is now a script:

```sh
core/tests/external/run-oils-differential.sh            # all 139 files
core/tests/external/run-oils-differential.sh builtin-set arith   # named files
# env: SILEX=path REF=path(dash) OUT=dir JOBS=n
```

It prints a per-file count of **dash pass + silex fail = a real gap** and
writes every one to `$OUT/gaps.txt` as `FILE<TAB>CASE#<TAB>result<TAB>
description`, which is the work queue. It is a diagnostic, not a gate:
`run-all.sh` does not run it (it needs dash installed), and the raw Oils
score keeps its own runner.

Two cautions are built into the script because both were learned the hard
way: it **snapshots the binary** into its temp dir, so a rebuild during a
sweep cannot change what is being measured, and it reports the run as
INCOMPLETE unless every selected file produced a non-empty TSV — a sweep
that silently loses files under-reports. Under heavy parallel load a file
can still hit the per-file timeout; rerun just that file by name.

## Reproducing

```sh
make core-external-fetch            # one-time, ~500MB
make core-external-test             # all suites; fails if any suite fails
SILEX=$(command -v dash) core/tests/external/run-smoosh.sh   # head-to-head
```

Suites run in a temp directory. If scratch files (`a1`, `cmd.sh`, `dir/`,
`link_*`) start appearing in the source tree, a runner has regressed to running
tests in place — which is how they came to be committed to this repo.
