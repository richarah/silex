# External Test Suite Scorecard

**Measured:** 2026-08-17, monorepo `core/`, glibc x86_64. Supersedes the
2026-08-10/11/12 figures. coreutils is measured on a native filesystem
(**0 failures**, the previous 27 were drvfs's no-op chmod), and the Oils
suite is used as a gap finder rather than a score, via a per-case
silex-vs-dash differential (**198 -> 167 -> 107 -> 86 -> 71 -> 59 -> 35**
real POSIX gaps as the queue was worked; silex now passes **1080** of the
2802 cases to dash's 957).

Before trusting any number here, read why an earlier version of this file was
meaningless.

## Why the old numbers were meaningless

Every gate in the test infrastructure was once wired so it could not report
failure:

- **Six runners ended in a hardcoded `exit 0`.**
- **`run-configure.sh` tested `tail`'s exit status**, not configure's
  (`if cmd | tail -50; then`). `FAIL` could never increment, so the report
  always said `Failed: 0` — the exact string CI grepped for. A run in which
  curl's configure died with `'echo' command not found` was recorded as
  **5/5 PASS**.
- **`run-modernish.sh` counted `^FTL` lines with `grep -c … || true`.** When
  modernish failed to launch, the count was 0, so the suite reported
  *"Fatal bugs (FTL): 0 — Perfect score!"* — a clean sheet awarded *because*
  it was too broken to run.
- **CI's "critical requirements" step treated a missing results file as a
  pass.** Eight of ten suites executed **zero tests** (a relative binary path
  broke after each runner `cd`'d into its own repo).
- The vendored **smoosh checkout had been corrupted by in-place runs**: ~50
  `.out`/~180 `.err` expected-output files had been *generated by silex itself*,
  so those tests compared silex against its own output and passed by
  construction.

That is fixed. Suites can now fail, and a suite that executes zero tests is a
failure, not a pass.

## Where the last smoosh failure is

One test, and it is unwinnable by construction: `builtin.times.ioerror`
compares stderr against the literal line `smoosh: times: I/O error` — the
reference implementation's own name. Every cluster that was listed here on
2026-08-10 (job control/monitor, traps in sub/supershells, non-lexical
break/continue, interactive features, parse-error exit paths, builtin flag
gaps) is fixed and green.

Known real gaps that remain: **35 Oils cases where dash passes and silex
does not**, of which about half are unwinnable by construction or are
deliberate divergences (see the 2026-08-17 section below) — that list is the POSIX to-do queue, and it is now generated
mechanically (see below). sed's dot-matches-NUL corner needs a

### What the 2026-08-13 queue run fixed (167 -> 107)

Working that queue file by file drove out 50+ POSIX bugs. The ones worth
knowing about:

- **`set -` / `set +`**: a lone `-` turns off `-x`/`-v` and stops option
  processing without clearing `$@`; a lone `+` is an ignored flag. `set - a b`
  used to produce the positionals `- a b`.
- **`-v` (verbose) is implemented**, not just accepted: the lexer echoes input
  to stderr as it consumes it, so `sh -v script` and `set -v` behave like dash.
  `$-` now also reports `v` and `i`.
- **Quoted nulls are fields.** `""$A` with `A="  abc  "` yields `["", abc]` —
  an empty quoted region left nothing for the splitter to see, so the field
  vanished. A zero-width placeholder now carries it through the split.
- **Mixed `$x"$@"` words** split on IFS *and* on the `"$@"` boundaries;
  previously the `"$@"` path returned early and glued `$x` to `$1`.
- **Arithmetic is pre-expanded** (POSIX 2.6.4): `$((1 + $(echo 1)${u:-3}))`,
  `$((1 + $((2+3))))` and backticks all work, newlines are whitespace inside
  `$(( ))`, and trailing garbage (`$((1 + 2.3))`, `$((echo hi))`) is the shell
  error it should be instead of a silent `0`.
- **POSIX 2.8.1 error consequences**: assigning to a read-only variable, and a
  usage error in a special builtin (`set -o bogus`, `shift 3`, `trap -1`), end
  a non-interactive shell — `|| true` does not rescue them.
- **`trap 0 2` resets** those conditions instead of installing an action named
  "0"; `trap 'foo'` with no condition is an error.
- **`wait`** takes several pids, reports the last one's status, returns 127 for
  a pid that is not our child, 2 for a non-numeric operand, and 0 for a plain
  `wait`.
- **Async fork race**: signals are blocked across the `&` fork, so a signal
  aimed at the new job before it cleared the inherited handlers no longer runs
  the parent's trap action twice.
- **Assignment-only commands take their redirections first**, so
  ``paths=`tr '\n' ':'`<<EOF`` reads the here-document. It previously read the
  shell's own stdin and **hung**.
- **Lexer**: a `$` that starts no expansion is literal and does not swallow the
  next character — `"$"` no longer eats its closing quote (the rest of the line
  joined the word) and `echo $;` no longer eats the `;`.
- Plus `getopts` (bad name, OPTIND past a bad flag, reset on `set`), `read`
  option validation, `pwd` after the cwd is removed, `chdir`, `${###}`,
  `test -a FILE`, `PS4` expansion (with the fork bomb that hid in it),
  `sh -l`, `sh -oo a b`, and `set -o vi/emacs`.

### What the 2026-08-14 queue run fixed (107 -> 86)

Twenty-one cases, from six files' worth of queue. One parser bug accounted
for a third of them:

- **`N >` is not a file descriptor.** POSIX 2.10.2 rule 2 makes a digit word an
  IO_NUMBER only when the redirect operator follows with NO blank between
  them; the lexer never recorded adjacency, so `seq 5 6 > f` ran `seq 5` and
  pointed **fd 6** at the file, and `bytes 512 > ok.txt` called the function
  with no arguments at all. Any command whose last operand was numeric and
  was followed by a redirect silently lost that operand. Tokens now carry a
  `blank_before` flag. This alone fixed `redirect-command` 3 and 6,
  `builtin-process` 21, `redirect` 5 and `smoke` 9.
- **A redirect cannot prefix a compound command.** `>f for i in ...` has no
  production in the grammar; it parsed as a redirect-only command followed by
  an unredirected loop, so the output the script meant to capture went to the
  terminal. Now a syntax error (status 2), as in dash. Fixed `assign` 9 too.
- **`set -e` and `!`.** POSIX 2.9.2 exempts a pipeline beginning with `!` --
  and that covers the pipeline's OWN result, not just the negated command.
  Running the inner command in a condition context was not enough: `! true`
  inverted 0 to 1 and the shell then died on the 1.
- **NUL bytes are dropped, not terminators.** A shell variable is a C string,
  so `s=$(printf '.\0.')` truncated at the NUL and threw away the rest. dash
  and bash skip NULs and keep the remainder; command substitution and `read`
  now do the same, which also settles the `${s#?}` cases from Oils issue 2269.
- **`command -p` was parsed and then ignored** on the execution path (only
  `-v` honoured it), so it would happily run a utility the caller had planted
  on `$PATH` -- the one thing `-p` exists to prevent.
- **`ulimit` validation**: extra operands were dropped and `strtoull` was fed
  the sign, so `ulimit -f -- -42` wrapped to a limit of 2^64-42 blocks and
  reported success. Extra operands, `-a` with an operand, and negative numbers
  are now errors (status 2), and `trap`/`kill` learned the rest of the POSIX
  signal names (`XFSZ`, `XCPU`, `VTALRM`, `PROF`, `SYS`, `IO`/`POLL`) -- a
  script's `trap - XFSZ` before deliberately exceeding `ulimit -f` used to
  fail with "bad trap".
- **`date` operands**: a bare operand is the obsolescent
  `MMDDhhmm[[CC]YY][.ss]` set-the-clock form, not a format string, and there
  is at most one `+FORMAT`. `date %x` printed the current time and exited 0
  where every other date rejects it, so a configure probe that tests
  `date FMT` to choose a code path took the wrong branch.

### What the second 2026-08-14 queue run fixed (86 -> 71)

Fifteen cases from five root causes. Two of them were not POSIX corner cases
at all but bugs that silently corrupted ordinary scripts, and both were found
only because the queue pointed at the file:

- **`env CMD` replaced the shell.** `env` EXECS the command it is given --
  correct for a standalone /usr/bin/env, fatal for an applet dispatched
  in-process. `echo a; env echo b; echo c` printed a and b and then the shell
  was simply gone: exit 0, `c` never reached, no diagnostic. Applets are
  dispatched ahead of PATH by design, so this hit every `env CMD` in every
  script. It now runs in a fork, as the `sh` applet already did for the same
  reason. Fixed `shell-bugs` 0 and `tilde` 13.
- **A `VAR=val` prefix never reached an APPLET's environment.** An external
  utility gets the binding from the exec and a shell builtin had its own
  apply/restore, but an applet runs in-process and reads getenv(), so the
  binding was invisible: `TZ=UTC date` printed local time and `LC_ALL=C sort`
  sorted in the caller's locale. Both silently produced wrong output rather
  than failing. The restore covers the export FLAG too, so a variable that
  existed unexported is not left exported.
- **A command whose words expand to NOTHING** still performs its
  redirections and assignments and completes with the status of the last
  command substitution (POSIX 2.9.1). silex returned 0 and did none of it:
  `$(exit 42)` reported success, `set -e; $(false)` did not fire, `$u > f`
  never created f, and `foo=alive! $unset` rolled the binding back with the
  temp overlay instead of keeping it. Which substitution is "last" follows
  POSIX expansion order -- words (step 2) before assignments (step 4) -- so
  `foo=$(exit 1) $(exit 2)` is 1, not 2. Fixed `exit-status` 8, 9 and 10 and
  `temp-binding` 3 (Oils #2411, #2416).
- **`test`/`[` now follows dash's expression grammar** in the three places
  POSIX leaves the form unspecified: a primary that runs out of words is a
  missing expression (false) rather than a syntax error, which is the whole
  `[ -a -a -a ... ]` ladder; a binary operator beats a unary one but only
  when its right operand exists (`test x -a -f = y` is the string compare
  "-f" = "y", while `[ x -a -e = ]` is a file test on "="); and `-t` with a
  non-numeric operand is status 2, not a quiet false. `test $# -ne 0 -a
  "$1" != "--"` -- the sqsh configure idiom behind Oils #2409 -- is the case
  that cares. Fixed `blog2` 1/3/5/7, `bool-parse` 0, `builtin-bracket` 30.
- **`printf` never recognised `--`**, so it took "--" itself as the FORMAT
  and swallowed every argument, printing a bare "--" and exiting 0. And
  `head`/`tail` accepted `--bytes=4` but not `--bytes 4`, which getopt_long
  takes for the same option -- that is what made `builtin-umask` 7 look like
  a umask bug when the umask output was fine and the pipeline's `tail` was
  not. Fixed `builtin-printf` 8 and 9, `builtin-umask` 7.

Two deliberate divergences remain:

- After an expansion error (`set -u`, or `${x?msg}`) an INTERACTIVE silex
  aborts only the offending command and keeps running the rest of the input,
  where dash and bash discard the whole input line. smoosh's
  `semantics.interactive.expansion.exit` requires silex's behaviour and Oils'
  `builtin-set` case 5 requires dash's; silex follows smoosh, its POSIX
  ground truth, and the Oils case stays in the gap list.
- **Applets are dispatched before the PATH search**, so a `tr` earlier on
  `$PATH` does not shadow silex's in-process `tr`, and `command -v tr` names
  the builtin rather than a path. POSIX 2.9.1.1 permits a found utility to
  fall back to the built-in version, and dispatching in-process is the point
  of the monolith; `builtin-meta` cases 1 and 10 want dash's answer and stay
  in the gap list. Note that this is about the shell's own dispatch: the
  toybox and coreutils runners exercise the applets through a PATH of silex
  symlinks and are unaffected.

### What the 2026-08-15 queue run fixed (71 -> 59)

Twelve cases. The theme this time is input the shell used to **accept**: every
one of these ran with status 0 and no diagnostic, which is worse than a wrong
answer, because a typo produced no signal at all. Three of them corrupt
ordinary scripts and none was caught by any suite.

- **An unterminated quote or substitution was silently accepted.** `echo 'abc`
  printed abc and exited 0. The scanners hit EOF, stopped, and handed back an
  ordinary WORD -- there was no channel for "this construct never closed". The
  damage is not the missing error but what the runaway construct does to the
  rest of the file: `echo $(echo inner` followed by `echo after` printed
  "inner after", having pulled the following lines into the substitution and
  run them there. All six forms (`'` `"` `` ` `` `$(` `${` `$((`) now report
  and exit 2 like dash. Fixed `parse-errors` 17 and 18, `command-sub` 28.
- **A leftover scope terminator was diagnosed one command too late.** The list
  parsers stop on `done`/`fi`/`esac`/`then`/`else`/`elif`/`do`/`)`/`}`/`;;` --
  that is how a compound body knows it has ended -- so at top level
  `echo 1 ;; echo 2` handed back `echo 1`, the driver ran it, and only the
  NEXT parse call met the stray `;;`. dash prints nothing and exits 2. Now
  checked where the command is handed back, not where the next one is fetched.
  Fixed `parse-errors` 19, `toysh-posix` 20.
- **A separator with no command before it was a no-op**: `;`, `; echo b`,
  `echo a; ; echo b` and `cmd &;` all ran. The grammar has no production for
  any of them. `&;` appeared in silex's own `$!` test, which had only ever
  passed because of this. Fixed `posix` 9.
- **A syntax error inside `$( )` was not a syntax error of the script.**
  `echo $(if true)` substituted the empty string and exited 0: the body is
  parsed lazily in the forked child, so the parse error became only that
  child's exit status -- indistinguishable from a command that ran and failed.
  The child now reports it on its own out-of-band pipe. Two traps in that:
  the fd must be CLOEXEC (the child is `disposable` and may tail-exec), and
  the parent must reap the child and read NON-BLOCKING, because a descendant
  of the child inherits the write end across fork and one that outlives it
  holds the pipe open forever -- modernish's LOCAL deadlocked on exactly that,
  40 minutes for 4 seconds of CPU. Fixed `toysh-posix` 21, `array` 46.
- **An unknown `${}` operator returned the plain value**, as if the operator
  had never been written: `${a&}` printed $a, and every bash-only modifier
  degraded silently instead of failing. Same "bad substitution" the no-name
  case (`${%}`) already reported. Fixed `var-sub` 0.
- **A quoted glob metacharacter did not survive pathname expansion.**
  `echo \[???\]` matched the file named `?`: quote removal runs before the
  field reaches glob(), so the escaped brackets arrived as a real bracket
  expression and the shell confidently returned the wrong file. Pathname
  expansion now builds its pattern with the same quote-aware builder `case`
  uses -- but only for a LITERAL word, because that builder expands what it is
  given and using it on a word carrying an expansion is a SECOND expansion of
  it (`$(...)` twice, `${x=v}` twice; modernish's LOCAL aborted with
  "_Msh_2: unbound variable" before the gate was narrowed). The builder itself
  also had to start escaping `- ! ^ :`, which are metacharacters only inside a
  bracket expression -- that alone fixed `case - in [C\-D]`, which had never
  matched. Fixed `glob` 15, 18, 19.

Two more bugs fell out of the suites rather than the queue:

- **`export -p`, `alias` and `trap` listings were not re-inputtable.** All
  three printed the value between bare quotes, so `export V="a'b'c"` listed as
  `export V='a'b'c'`, which re-reads as `abc`; with an odd number of quotes it
  is not parsable at all, making `eval "$(export -p)"` -- the standard
  save/restore idiom -- a syntax error. POSIX requires all three to be
  suitable for reinput. `set` and `readonly -p` already used the escaping
  helper; `export -p` had a TODO next to it. Found by ShellSpec, whose
  `shellspec_list_envkeys` evals `export -p` output: it had been losing the
  quotes all along and only started failing once an unterminated quote became
  a real error.
- **`grep` returned 0 after failing to open a file**, as long as some other
  file matched -- a match overwrote the error. A script could not tell a clean
  search from one that never opened half its arguments. GNU: any error is exit
  2, with `-q` the documented exception. The edge test covering this was
  itself wrong (it passed two `--` and expected the second to vanish; one ends
  the options, a second is a file named "--", exactly as GNU treats it) and
  had only passed because of the same bug. The edge suite is green again.

### What the 2026-08-17 queue run fixed (59 -> 35)

Twenty-four cases. No single theme this time -- the queue had been worked
down to its individually-argued remainder -- but three of the fixes lose or
corrupt data in ordinary scripts, and one of those was silent.

- **Field splitting split the word's own text, not just the expansion.**
  POSIX 2.6.5 splits "the results of expansions"; a literal IFS character
  typed in the word is not a separator. With `IFS=x`, `echo ${w}x` dropped
  the trailing `x` outright -- it started an empty field, and empty fields
  are discarded -- so the argument the script wrote never reached the
  command. Literal separators are now protected by the same guards a quoted
  region uses. The WORD of a `${v-word}` is part of the *result* and so is
  still split, which needed a flag (`in_subst_word`) to tell the two apart:
  `IFS=x; echo ${v:-AxBxC}` is three fields, `echo ${w}x` is not.
  Fixed `word-split` 54.
- **Unquoted `$@`/`$*` joined with a space, whatever IFS said.** The join is
  then re-split by IFS, which is only equivalent while IFS contains a space:
  with `IFS=zx`, `for i in $@` saw the single field "a b c " where every
  other shell sees "a b" and "c". Now the separator is IFS's first
  character. Relatedly, an IFS that is set but EMPTY joins `"$*"` with
  nothing, not with a space -- conflating "empty" with "unset" made
  `set -- "" ""; IFS=` yield " ", so `${*:-word}` saw a non-null value and
  skipped the default. Fixed `word-split` 47, `var-op-test` 22.
- **`a=(1 2 3)` ran the array elements as commands.** POSIX has no
  production for `(` after an assignment or a command word, so it is a
  syntax error; silex parsed it as the assignment `a=` followed by the
  subshell `(1 2 3)`, which then executed `1`, `2` and `3`. The same rule
  covers `A=a B=(b b) cmd`. An assignment prefix also ends reserved-word
  recognition -- `FOO=bar for` looks for a program called "for" -- which is
  what dash does and what makes the paren rule reachable.
  Fixed `arith-context` 15, `array` 3, 27, 28, 47, `assign` 10.
- **A here-document delimiter was only unquoted at its outer edge.**
  `<<'EOF'"2"` should end at a line reading `EOF2`; stripping the outer pair
  produced the delimiter `EOF'"2`, which nothing matched, so the here-doc
  swallowed the rest of the file. The delimiter is now the word after full
  quote removal, and any quoting anywhere in it suppresses expansion.
  Fixed `here-doc` 12.
- **A flow-control sentinel escaped as `$?`.** `return` at the top level of a
  script printed `status=1002` on the next line, and `sh -c 'return'` exited
  234 (1002 & 0xff). There is no enclosing function or loop at the top level:
  `return` ends the script, `break`/`continue` are a no-op. The distinction
  that makes this safe is *which* string is the script -- an `eval` argument
  or trap action nested inside must still propagate, or
  `f() { eval "return 3"; }` never returns from f (smoosh
  `builtin.eval.break` is the canary; a first attempt keyed on nesting depth
  broke it). Fixed `strict-options` 5, `loop` 23.
- **A syntax error exited 0 if the script had an EXIT trap.** The trap's own
  status was taken as the shell's on normal termination, which is right for a
  script that ran, but a script that would not parse fails with 2 whatever
  happens afterwards. Fixed `builtin-trap` 19.
- **A command that could not be executed reported 127, not 126**, so a script
  could not tell a typo in the name from a missing `chmod +x`. And a command
  whose REDIRECTION failed was still looked up: `[[ -f < ]]` printed both
  "cannot open" and "command not found" and exited 127, when the redirect
  alone had already decided it. Fixed `command_` 1.
- **An in-process applet died of SIGPIPE in place**, taking the shell with
  it: `(cat </dev/zero; echo $? >&7) | true` lost the `echo` -- the subshell
  was simply gone -- where the same line with `/usr/bin/cat` prints 141. A
  handler over the applet call keeps the process alive and lets the COMMAND
  report 141 the way the external utility it stands in for would.
  Fixed `divergence` 3 (oils #2530).
- **An alias was not substituted after a redirection prefix.** POSIX
  substitutes for the command word, which may be preceded by redirections;
  the parser only offered the head of a pipeline stage, so `>out e_ 1` ran a
  program literally named `e_`. Fixed `alias` 32.
- **`n>&n` was an error when n was closed.** Duplicating a descriptor onto
  itself asks for nothing, and dash and bash both allow it; `: 3>&3` aborted
  the script, because a redirection error on a special builtin is fatal.
  Fixed `redirect` 13.
- **Inside `"..."`, a backtick body did not see `\"` as `"`.** The enclosing
  double quotes get their say first, which is why the backtick and `$( )`
  spellings of the same line differ in every shell -- and why virtualenv's
  `activate` is written the way it is. Fixed `command-sub` 15.
- **The scan for a `${...}`'s closing brace ignored `'...'` inside `"..."`.**
  `"${var#'}'}"` ended at the brace between the quotes, leaving `'}` as
  trailing text. dash and bash both honour the quotes for the scan (whether
  they are then REMOVED is a separate question, and silex keeps them, as
  dash does). Fixed `var-op-strip` 26.
- Smaller ones, each a case where the shell answered a question wrongly
  rather than not at all: a function name carrying an expansion
  (`$foo-bar() { ...; }`) defined a function no call could ever name, and is
  now a syntax error (`func-parsing` 9, 10); a reserved word may name the
  `for` variable, so `for in in a b c` parses (`loop` 3); `local x=v; local x`
  no longer wipes the value the first declaration gave it (`builtin-vars`
  36); and `type` reports aliases and functions at all -- it used to say
  "not found" for a function the next line could call -- and calls out the
  special builtins, whose assignment-persistence and fatal errors are
  observable (`builtin-type` 4).

### What the 2026-08-18 scan rewrite fixed (35 -> 34)

`var-sub-quote` 31 (`"${foo%d'}"` is a syntax error) was the case in the
queue, but chasing it found that the LEXER was counting braces to find a
`${...}`'s closing `}` while expand.c's `scan_braced_end()` was scanning
recursively -- the two disagreed, and the double-quoted forms usually
survived only because the word reached expand.c intact and was re-parsed
there. Measured against dash and bash, silex was wrong on `${x:+a{b}`,
`${x:+$(echo })}`, ``${x:+`echo }`}`` and `"${x:+'{'\}}"`, none of which any
suite covered. A bare `{` is data in every POSIX shell; only `${` opens a
level. The lexer now scans, `'` quotes inside `"..."` in a pattern operand
(where both shells agree) but not in a `-` operand (dash's rule, kept), and
`\}` loses its backslash in a `"${v-...}"` word -- which cleared modernish's
BUG_PSUBBKSL1 as a side effect.

### What remains, and why (34 cases)

About half of the remainder is not winnable without giving something up:

- **Five** want a shell whose `$0` ends in "sh" (`var-num` 2/3/4,
  `spec-harness-bug` 0, `vars-special` 8). silex is named silex.
- **Three** follow from applets outranking PATH, which is a deliberate design
  decision (`builtin-meta` 1, 10, `builtin-type` 1); see the note on it.
- **Two** (`blog-other1` 1, 2) pass in dash only because dash reads ahead
  over a piped script, so a command that reads stdin finds it already
  drained. POSIX requires the offset to point just after the command the
  shell has read; bash and silex both honour that, and both "fail" here.
- **One** (`func-parsing` 3) wants dash's unbraced function body
  (`f() ls`), which POSIX's grammar does not have and bash rejects too.
- **One** (`redirect` 32) wants dash's single-digit limit on a redirection's
  fd prefix; `exec 10>file` is useful and silex's own machinery parks
  descriptors at 10 and above.
- **Six** are judgment calls left open on purpose, each recorded where the
  code makes the choice: whether an EXIT trap's status becomes the shell's on
  normal termination (`builtin-trap` 18 -- dash and bash say no, smoosh's
  `builtin.trap.subshell.false.exit` says yes, and silex currently follows
  smoosh); whether `printf -v` is an illegal option (`builtin-printf` 4);
  whether `local` is a special builtin (`command-parsing` 0 -- dash says yes,
  bash no); whether a symbolic umask permcopy reads the original or the
  running value (`builtin-umask` 22); dash's `''}` for `"${var-'}'}"`
  (`var-sub-quote` 38 -- bash and silex print `'}'`); and 1-vs-2 as the
  status of a failed redirection (`dbracket` 25 -- bash 1, dash 2).

The rest are real and open: here-docs and unterminated quotes inside alias
values (`alias` 25, 39), tempenv unset nesting (`ble-unset` 3, 4), three
`builtin-cd` cases, `read` with backslash continuation and a non-default IFS
(`builtin-read` 24), `set -u` exit status under `-i` (`builtin-set` 5), an
assignment prefix on `exec` (`builtin-special` 3), trap
listings inside subshells (`builtin-trap` 0, 29), a here-doc delimiter
containing `$( )` (`here-doc` 6), tilde expansion in a `${v-word}`
(`tilde` 11), an all-empty `$*` under a non-whitespace IFS
(`toysh-posix` 18), and `$PWD` export (`vars-special` 1).

That is 18 unwinnable-or-deliberate and 16 open, which is the whole 34: the
list above is the sweep's `gaps.txt` in full, not a selection from it.

## Finding real gaps: the silex-vs-dash differential

The Oils suite is mostly bash/ksh extension tests that no POSIX shell
passes, so its raw pass count says little. Running BOTH shells in one
sh_spec.py invocation and diffing per case separates signal from noise.
That is now a script:

```sh
core/tests/external/run-oils-differential.sh            # all 139 files
core/tests/external/run-oils-differential.sh builtin-set arith   # named files
# env: SILEX=path REF=path(dash) OUT=dir JOBS=n
```

It prints a per-file count of **dash pass + silex fail = a real gap** and
writes every one to `$OUT/gaps.txt` as `FILE<TAB>CASE#<TAB>result<TAB>
description`, which is the work queue. It is a diagnostic, not a gate:
`run-all.sh` does not run it (it needs dash installed), and the raw Oils
score keeps its own runner.

Two cautions are built into the script because both were learned the hard
way: it **snapshots the binary** into its temp dir, so a rebuild during a
sweep cannot change what is being measured, and it reports the run as
INCOMPLETE unless every selected file produced a non-empty TSV — a sweep
that silently loses files under-reports. Under heavy parallel load a file
can still hit the per-file timeout; rerun just that file by name.

## Reproducing

```sh
make core-external-fetch            # one-time, ~500MB
make core-external-test             # all suites; fails if any suite fails
SILEX=$(command -v dash) core/tests/external/run-smoosh.sh   # head-to-head
```

Suites run in a temp directory. If scratch files (`a1`, `cmd.sh`, `dir/`,
`link_*`) start appearing in the source tree, a runner has regressed to running
tests in place — which is how they came to be committed to this repo.
